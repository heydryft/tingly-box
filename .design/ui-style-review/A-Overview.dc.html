0 · 怎么读这份评审
上一轮评审改的是零件（按钮、词汇、状态），这一轮问的是整体：视觉语法该不该换。同一个 Agent 页画成四张：现状，A 收紧，B 同骨架换语法，C 换壳。再用 B 的语法画 Dashboard，看它能不能推广。
1 现状
标准 MUI 后台：到处是边框和卡片，实心蓝同时表示选中和主操作，四条规则几乎一样的路由图占满两屏。
2 方案 A · 收紧
不改结构，只把圆角、颜色、字号收进令牌，选中态改浅蓝。观感几乎不变，只是更整齐。
3 方案 B · 换语法（推荐）
rail+sidebar 骨架不变。去掉嵌套边框，用分隔线分组；选中态用浅灰底和细色条；颜色只表示状态；规则折成摘要行，点开才出路由图。
4 方案 C · 换壳
去掉 rail 和 sidebar，换成顶栏标签 + ⌘K + 右侧实时活动列。像文档一样的单列页面，更有性格，但所有人要重新学习。
5 B 推广到 Dashboard
指标卡变成一条数字带，页面标题下一行回答"现在正常吗"，筛选变胶囊，图表去掉彩色。
五条贯穿 B 的视觉规则
  1. 一层面。页面底色之上只有一层内容，分组用留白和 1px 分隔线，不再嵌套边框。
  2. 选中不是主操作。选中用浅底色加细色条；实心深色只给页面唯一的主操作。
  3. 颜色只说状态。绿、橙、红表示健康、等待、错误，其余全是中性色。
  4. 排版只有四档。页面标题、区块标题、正文、辅助；URL、key、模型名用等宽，数字用等宽数字。
  5. 浏览是行，编辑才是图。规则默认一行摘要，展开才出现路由图。
这些是示意稿，用的是 mock 数据；深色和中文的表现没有单独画。要选方案，先看 2 到 4 三张。
